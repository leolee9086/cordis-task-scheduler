# 调度模型与实现边界

本文描述 alpha.4 的多环、资源分派与可选持久队列。公共用法见 [README](../README.md)，具体类型位于 [types.ts](../src/types.ts)。

## 环级关系与共享需求

每个环独立持有容量、就绪组、执行计数和资源用量。候选选择依次考虑到期公平预算、rank 和同 rank 轮转。需求聚合采用静态 rank、声明次序、priority；动态公平预算只影响分派，不改变任务的有效需求身份。

容量归属为首次准入环；运行额度归属为本轮取得额度的环。执行中的提权会传播给子任务并影响抢占关系，但不移动已占资源的计账。这个区分使撤销前台需求可以正常降级，不会因为后台容量已满而拒绝撤销。

`maxBypass` 记录等待环被越过的分派次数，提供服务机会而非墙钟期限。公平保护窗口为 quantum 与累计重启开销两倍的较大值。可保存检查点的任务在检查点后重置重启开销；不可中断任务仍须等退出。没有检查点的长任务获得连续服务可能延长前台等待，配置时须结合实际负载评估。

## 分派索引与成本

[DispatchIndex](../src/dispatch.ts) 按环和资源向量分组，每组贡献一个头部。资源阻塞挂整个组，key/lane/segment 阻塞挂单项，通过反向等待索引唤醒。任务结束后删除空资源组、空等待集合和运行身份索引。

环内等待权重消去共同的当前时间项，入队、提权、撤销只更新相关索引堆。每次 pump 重新检查受阻资源组头部，避免新的 pump 绕过既有多资源队首；资源保留允许队首积累全部额度，不妨碍不相交资源执行。

| 路径 | 当前成本与限制 |
| --- | --- |
| 同 key 定位、运行 key/lane 检查 | Map/Set 查询 |
| 租约需求聚合 | 索引堆增删，O(log d)，d 为该任务需求数 |
| 单项排序变更 | 相关任务堆和组头堆更新，无全等待队列 rebuild |
| 候选环选择 | O(r)，r 为配置的环数 |
| pump 资源重试 | 遍历受阻组；最坏随资源向量种类增长 |
| key/lane/阶段阻塞 | 唤醒相关等待集合；同组多项均阻塞时仍需逐项检查 |
| 抢占规划 | 仅阻塞时检查运行集合并排序，O(a log a)，a 为运行数 |
| 批量准入 | 逐项验证，容量溢出时才搜索可驱逐候选 |
| 新子依赖 | 遍历显式依赖图和运行祖先；大图仍有遍历成本 |
| 观测 | 有界环形历史；通知按订阅者遍历保留事件，溢出报告 gap |

这里没有宣称所有操作 O(1)。持续负载验证覆盖了有限真实文件流、抢占、后台进展和索引回收；未建立覆盖所有资源拓扑或长期生产负载的性能上界。

## 执行与队列边界

执行 Promise 退出后才归还资源。`close()` 同步撤销注册名，但旧代 active 集合仍独立保留至退出；新旧代通过全局 key/lane 索引互斥。阶段最高启动值在取得执行额度时更新，禁止观察回调趁微任务间隙回插更早阶段。

编排器不占执行资源。`submitChild` 只接受同调度器队列，建立引用计数依赖边，拒绝环和祖先 lane/阶段阻塞。父执行结束释放所有子需求。`drain` 封闭外部提交，同时允许已有编排器完成其子工作。

批量准入先检查身份约束和容量，全部通过后才发布。后续需求传播在批次发布完成后交付，避免回调打断半批准入。相同 key 的 payload 版本由调用方编码进身份，lane/segment/resources 则由核心逐项验证。

## 持久队列边界

[SQLite 模块](../src/sqlite.ts) 与内存调度核心分离。它使用调用方连接、显式 namespace 和 codec 版本；所有写操作用同步 BEGIN IMMEDIATE 事务。队列版本只随成功变更增长，任务 revision、入队 sequence 和队列 version 均检查安全整数范围。

执行器取得资源后按候选 revision 领取，凭 owner/token/revision 结算；业务结果可通过 settle 回调与终态共同提交。输入身份、需求和领取凭据在回调前固定；codec 需保持纯同步，禁止队列重入。调用方已有事务不会被队列误回滚，业务回调不得自行结束事务或修改调度表。

恢复以“调用方确认指定旧 owner 已退出”为前提，明确 retry 或 fail；不凭超时猜测外部副作用。这个模块不处理应用级投递语义、用户输入轮次或网络 exactly-once。持久候选必须重新进入真实调度器，而不能把诊断事件或内存快照当作可恢复日志。

## 参考设计对应关系

参考：[s-forge](https://github.com/leolee9086/s-forge)、[textureBackerDemo](https://github.com/leolee9086/textureBackerDemo)、[SACAssetsManager](https://github.com/leolee9086/SACAssetsManager)。下面是实际采用的通用边界，不表示 API 兼容或全部业务语义等价。

| 参考能力 | 当前对应 | 应用仍负责 |
| --- | --- | --- |
| s-forge agentqueue 的独立环和容量 | RingPolicy、环内索引、rank/抢占关系 | 环策略选择 |
| SessionInbox lane 与目标 turn 领取条件 | lane 隔离、显式子依赖、阶段屏障 | turn/投递条件等业务有效性 |
| transaction 的候选保存后发布与版本检查 | 批量准入、queue.version、SQLite 事务 | 外部副作用的幂等性 |
| 持久批量领取、释放、恢复 | claim/release/recover 与持有者凭据 | 确认旧执行者退出、业务资源版本 |
| my-async-queue 优先级组、容量策略、idle | 环内策略、evict/reject/throw、onIdle/drain | 任务分类和背压 |
| 原 SAC 可见优先与暂停队列 | 共享 demand、可中断执行、资源所有权 | 实际资源执行器与视口租约 |

参考实现按执行代码判断：RingQueue 全空后的阻塞 select 不保证多通道同时就绪仍严格按环取；SessionInbox.Take 的投递语义两轮扫描不等于 InputPriority 排序；my-async-queue 的 activeSegmentTasks 耗尽不代表本阶段已启动工作全部退出。此处阶段屏障明确等待实际退出，但不自动要求上一阶段成功。
